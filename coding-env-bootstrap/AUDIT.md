## Findings

### 1. Provider API tokens sit in `settings.json` — fix before any machine copy

`~/.claude/settings.json` contains `env_minimax` and `env_zai` blocks holding live
third-party API tokens in plaintext. They are **inert as written** — Claude Code reads
`env`, not `env_*`, so these are parked profiles, not active config. They are still
plaintext credentials in a file that gets backed up, synced, and pasted into issues.

**Do:** move them to `~/.config/agent-keys.env` (mode `600`, outside every repo), source
that from a small shell wrapper per provider, and delete the blocks from `settings.json`.
Rotate them if that file has ever left the machine.

**Never** carry this file to a new machine as-is — `BOOTSTRAP.md` §4 reconstructs the
portable subset by hand for exactly this reason.

### 2. `skipDangerousModePermissionPrompt: true` should not travel

Reasonable on a personal laptop with the operator watching. On an unattended production
box it removes the last confirmation before destructive commands, and a remote agent has
no one to notice. `BOOTSTRAP.md` §4b replaces it with an explicit `permissions.allow`
list, which gives the same "stop prompting me" outcome with a bounded blast radius.

### 3. `~/.shared-ai-skills` is not under version control

101 entries, 74 of them real directories rather than symlinks. It is not a git repo and
has no remote. The bulk is the gstack suite (reinstallable from upstream), and
the operator's own skills are symlinks into `~/.conan-agent-skills` (version-controlled)
— so the actual loss exposure is anything hand-authored directly inside
`~/.shared-ai-skills` that isn't upstream's.

**Do:** before wiping or migrating any machine, diff that tree against a fresh upstream
install and rescue anything local into `~/.conan-agent-skills`.

### 4. Skill count is a precision problem, not a context problem

89 skills load ~18k chars of descriptions (~4.5k tokens) into every session. That's small
against a large context window — the honest cost is **triggering ambiguity**, not size.
Overlapping pairs make the model pick between near-duplicates: `qa` / `qa-only` /
`playwright-skill` / `browse`; `design-review` / `frontend-design` / `a11y-audit`.

Three skills are also **malformed**: `interview-spec`, `spec-task-breakdown` and
`spec-task-breakdownclear` all start their `SKILL.md` with `name:` instead of the opening
`---` delimiter. The frontmatter is never parsed, so the literal string `name: <slug>`
becomes each one's description — which is why they surface in the skill list as
"name: interview-spec" rather than a real trigger sentence. They cannot trigger on intent.
`spec-task-breakdownclear` is additionally a byte-identical copy of `interview-spec`
(same `name:`), i.e. a copy-paste artifact.

**Do:** on the production machine install only the operator's own skills plus the LSP
plugins (`BOOTSTRAP.md` §3b). On the workstation, delete `spec-task-breakdownclear`, add
the missing `---` to the other two, and pick one browser-QA skill as the documented
default.

### 5. No hooks, no global agents, no keybindings

`~/.claude/agents/`, `~/.claude/commands/`, and `~/.claude/keybindings.json` are all
absent, and no hooks are configured. Nothing is broken — but the operator's most repeated
complaint in the work history is changes landing that skipped the commit/push gates.
Those gates are per-repo (pre-commit/pre-push), which is the right level; the gap is that
nothing verifies they *ran*.

**Do:** keep enforcement in each repo's git hooks + CI. If a global belt-and-braces is
wanted, a `Stop` hook that refuses to end a session with a dirty tree in a repo that has
hooks configured is the smallest useful version. Not required for production.

### 6. Codex config is mostly portable, with one deliberate exception

`~/.codex/config.toml` carries a sensible auto-compact budget derived from the context
window and tool-output limit, plus a broad `[features]` set. Both port cleanly.

Two things that must **not** port: the long `[projects.*]` trust-level list (paths that
won't exist on the target, and trusting a path that doesn't exist yet is a footgun), and
the `notify` hook pointing at a local macOS app bundle.

`model_reasoning_effort = "low"` is set globally while Claude Code runs at
`effortLevel: "high"` — worth a deliberate decision rather than drift. If Codex is used
for real implementation work rather than quick lookups, raise it.

### 7. Toolchain is current and complete

node 24 / npm 11 / pnpm 11 / python 3.14 / uv 0.9 / git 2.47 / gh 2.95 / rg 15 /
jq 1.7 / ffmpeg 8 / docker 29. No action. `fd` is absent; `rg --files` covers its use,
so it stays optional.

### 8. MCP surface is minimal and correct

Two global servers: `context7` (universal — current library docs instead of model memory)
and XcodeBuildMCP (macOS/Xcode only). Nothing to prune. `context7` is the one to make
sure exists on every machine; it is also the cheapest fix for wrong-API-signature bugs.

## Recommended changes, ordered

1. **Move the provider tokens out of `settings.json`** and rotate if that file ever left
   the machine. *(security — do this first)*
2. **Don't carry `skipDangerousModePermissionPrompt` to any unattended machine**; build a
   `permissions.allow` list instead.
3. **Rescue any hand-authored skills from `~/.shared-ai-skills`** into the versioned repo
   before the next machine migration.
4. **Fix the three malformed `SKILL.md` frontmatters** (missing opening `---`), delete
   the `spec-task-breakdownclear` duplicate, and pick one default browser-QA skill.
5. **Decide Codex's reasoning effort deliberately** rather than leaving it at the default
   `low` while Claude Code runs `high`.
6. On the production machine, **install the curated subset**, not the whole workstation.


## Follow-up portability check, 2026-08-13

The previous default `refsync.py upgrade` path always re-applied the Claude workstation profile. On a remote machine without the browser/runtime sources, that made an otherwise valid core install fail on unresolved optional skills.

### Rule 1 — Never force a workstation load-out onto a headless target

Choose the narrowest profile supported by the target runtime. `auto` may fall back to `core`; an explicit workstation profile must fail closed when an entry is unavailable. This prevents a missing optional browser suite from blocking the production-owned skills and prevents a partial install from being reported as complete.

- **Fixed** — one-target `refsync.py` commands now use `auto`: no real browser or an incomplete workstation dependency tree selects `core` and reports the skipped set.
- **Fixed** — `harness.py` defaults to `core` for every target, including single-target production installs.
- **Fixed** — `status` and `upgrade` propagate load-out failures instead of reporting success after a partial apply.
- **Guard** — regression coverage lives in `coding-env-bootstrap/tests/test_harness.py`; `CONAN_AGENT_HEADLESS=1` or `CONAN_AGENT_BROWSER=0` forces the conservative decision.

Explicit `claude-dev` and `codex-dev` profiles remain strict. They are for workstations with their dependencies installed; they do not silently prune missing entries.
